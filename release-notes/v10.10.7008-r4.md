# Futu OpenD 10.10.7008-r4

本次发行在保持现有 Docker / Docker Compose 行为和安全默认值不变的前提下，
为 Linux/amd64 正式增加 Podman Compose 与 rootless Podman 支持。macOS Apple
Silicon 发行包继续使用 Docker Desktop 运行同一个固定 digest 的 Linux/amd64
镜像。

## Linux/amd64 快速开始

下载本 Release 中的：

- `futu-opend-10.10.7008-r4-linux-amd64.tar.gz`
- `futu-opend-10.10.7008-r4-linux-amd64.tar.gz.sha256`

校验并解压后准备配置：

```bash
sha256sum -c futu-opend-10.10.7008-r4-linux-amd64.tar.gz.sha256
tar -xzf futu-opend-10.10.7008-r4-linux-amd64.tar.gz
cd futu-opend-10.10.7008-r4-linux-amd64
cp env.example .env
chmod 0600 .env
```

安装以下任一运行环境：

- Docker Engine + Docker Compose；或
- Podman + Podman Compose，推荐以普通用户运行 rootless Podman。

编辑 `.env` 后，在私有终端首次登录并启动：

```bash
./futu-opend init
```

后续 remembered 状态后台启动及常用操作：

```bash
./futu-opend start
./futu-opend status
./futu-opend logs
./futu-opend stop
./futu-opend reauth
```

默认自动优先 Docker，再尝试 Podman。也可显式指定：

```bash
FUTU_CONTAINER_ENGINE=docker ./futu-opend start
FUTU_CONTAINER_ENGINE=podman ./futu-opend start
```

不需要 `alias docker=podman`，也不要使用 `sudo podman`。

## macOS Apple Silicon

下载同一 Release 中的 macOS 包及校验文件：

- `futu-opend-10.10.7008-r4-macos-apple-silicon.tar.gz`
- `futu-opend-10.10.7008-r4-macos-apple-silicon.tar.gz.sha256`

该包继续要求 Docker Desktop Linux container engine 和 Compose v2，并通过
amd64 仿真运行；它不是原生 arm64 OpenD，也不声明 macOS Podman 支持。

## 本次变更

- 集中实现 `FUTU_CONTAINER_ENGINE=auto|docker|podman` 检测，验证实际 Compose
  子命令，显式模式不会静默回退。
- Docker 配置验证继续使用 `config --quiet`；Podman 路径兼容不支持该参数的
  `podman-compose 1.0.x`，使用 `config` 并抑制正常输出。
- 源码初始化器和发行包六个管理命令全部使用同一安全的 Bash array 抽象。
- 启动器显式等待 `futu-key-init` 成功后才启动 OpenD，不依赖 Compose provider
  对 `depends_on.condition` 的具体调度行为。
- rootless Podman 保留固定 `10001:10001` 非 root OpenD 用户及命名卷内
  `0400` 私钥；SELinux 私钥 bind mount 使用私有 `Z` relabel。
- Dockerfile、Compose 网络、loopback API、RSA 检查、状态卷、Telnet/WebSocket
  默认关闭和 Docker 日志轮转行为保持不变。
- CI 在发布镜像前执行 Docker smoke 和 rootless Podman build/Compose/密钥卷
  smoke；不使用真实富途账号、密码或验证码。

## 已知限制

- `podman compose` 委托给外部 Compose provider，不同旧版本可能存在字段支持
  差异；请使用能够通过 `podman compose version` 的当前稳定 provider。
- SELinux `Z` relabel 只作用于宿主 RSA 私钥 bind mount；不要改用 `:U`、
  privileged 或放宽私钥权限。
- 首次登录或重新认证仍必须由用户在私有终端完成，可能需要手机或图形验证码。
- 健康检查不是登录成功或 API 业务就绪证明；真实 SDK 验收仍由用户单独执行。
- OpenD 归档摘要是经过审查的 TOFU 一致性锁，不是富途发布的签名。
- 本项目与富途证券没有隶属关系，不解锁交易、不下单，也不授予行情权限。
