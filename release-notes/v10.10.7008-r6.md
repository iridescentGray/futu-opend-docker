# Futu OpenD 10.10.7008-r6

本次发行将 Linux/amd64 发行包的 Podman 路径改为原生 rootless Podman，避免
依赖外部 `podman-compose` provider。Docker 和 macOS Apple Silicon 路径继续
使用 Docker Compose。

## 主要变化

- `FUTU_CONTAINER_ENGINE=podman` 直接使用 `podman volume`、`podman run`、
  `podman stop`、`podman ps` 和 `podman logs`。
- 不再要求安装 `podman-compose`，也不会把 Docker Compose 专用参数传给旧版
  provider。
- 保留现有 `futu-opend_futu-opend-key` 和
  `futu-opend_futu-opend-data` 卷名，不迁移或清空 RSA 密钥与登录状态。
- 保留 `futu-opend` 容器名、`127.0.0.1:11111` 发布、固定非 root UID/GID、
  密钥初始化、健康检查、有限重启与日志大小限制。
- 设置 `FUTU_SHARED_NETWORK` 时，Podman 直接连接预先创建的 external network，
  并提供 `futu-opend` 网络别名；停止服务不会删除该网络。

## Linux/amd64

首次登录或重新认证仍由用户在私有终端完成：

```bash
FUTU_CONTAINER_ENGINE=podman FUTU_SHARED_NETWORK=trading-backend \
  ./futu-opend init
```

后续 remembered 状态启动：

```bash
FUTU_CONTAINER_ENGINE=podman FUTU_SHARED_NETWORK=trading-backend \
  ./futu-opend start
```

不要执行 `podman volume rm` 或全局清理。真实登录、验证码和 SDK 就绪验收仍由
用户单独完成；健康检查不代表登录成功。
