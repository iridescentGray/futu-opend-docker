# Futu OpenD 10.10.7008-r5

本次发行在 r4 的 Docker、rootless Podman 和 macOS Apple Silicon 支持基础上，
新增由部署环境管理的可选可信容器网络，并为发行包的 `futu-opend` 管理命令
增加 `-h` / `--help`。

## 下载

Linux/amd64：

- `futu-opend-10.10.7008-r5-linux-amd64.tar.gz`
- `futu-opend-10.10.7008-r5-linux-amd64.tar.gz.sha256`

macOS Apple Silicon：

- `futu-opend-10.10.7008-r5-macos-apple-silicon.tar.gz`
- `futu-opend-10.10.7008-r5-macos-apple-silicon.tar.gz.sha256`

校验、解压并准备配置：

```bash
# Linux 使用 sha256sum；macOS 使用 shasum -a 256。
sha256sum -c futu-opend-10.10.7008-r5-linux-amd64.tar.gz.sha256
tar -xzf futu-opend-10.10.7008-r5-linux-amd64.tar.gz
cd futu-opend-10.10.7008-r5-linux-amd64
cp env.example .env
chmod 0600 .env
```

首次登录必须由用户在私有终端完成：

```bash
./futu-opend init
```

后续使用 remembered 状态启动，或查看帮助：

```bash
./futu-opend start
./futu-opend --help
```

## 本次变更

- 新增 `compose.integration.yaml`。非空 `FUTU_SHARED_NETWORK` 会让 OpenD
  加入一个预先创建、由部署环境拥有的 external network。
- standalone 默认行为不变；宿主机 API 仍只发布到 `127.0.0.1:11111`。
- `./futu-opend stop` 不删除 external network，也不删除 RSA 密钥卷或登录
  状态卷。
- `futu-opend -h` 和 `futu-opend --help` 显示所有管理命令，无需有效 `.env`
  或可用的容器引擎；非法命令继续返回用法错误。
- Docker 和 rootless Podman smoke 增加 integration Compose 模型及 external
  network 保留检查。

## 可选可信容器网络

网络必须先由部署环境创建。服务器同时安装 Docker 和 Podman 时应显式选择
Podman，确保两个服务使用同一个 rootless storage 和网络：

```bash
podman network exists trading-backend || podman network create trading-backend
FUTU_CONTAINER_ENGINE=podman FUTU_SHARED_NETWORK=trading-backend \
  ./futu-opend init
FUTU_CONTAINER_ENGINE=podman FUTU_SHARED_NETWORK=trading-backend \
  ./futu-opend start
```

宿主机 SDK 仍连接 `127.0.0.1:11111`；可信容器连接
`futu-opend:11111`。任何加入该网络的容器都能接触 OpenAPI，必须视为可信
客户端。

## 已知限制

- macOS 包通过 Docker Desktop 仿真 Linux/amd64 镜像，不是原生 arm64 OpenD。
- 首次登录、重新认证、验证码和真实 SDK 就绪验收仍由用户单独执行。
- 健康检查只证明进程和配置形态，不证明登录成功或 API 业务就绪。
- OpenD 归档摘要是经过审查的 TOFU 一致性锁，不是富途发布的签名。
- 本项目与富途证券没有隶属关系，不解锁交易、不下单，也不授予行情权限。
